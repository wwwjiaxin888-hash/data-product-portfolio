# 电商增长分析｜浏览、加购与购买的顺序验证

看板上每根条分别统计发生过该行为的去重用户数。为了判断样本能否支持分析加购流失，我把同一用户在同一商品上的浏览、加购和购买按时间串联，并对观察窗口和归因粒度做了对照。

## 指标定义

- 数据覆盖 2024-11-25 至 2024-12-04，包含 10,000 条清洗去重后的行为日志、880 名用户和 8 个品类。
- 每个「用户 × 商品」组合以样本中第一次浏览作为起点。仅纳入截至最后一条日志仍有完整 24 小时观察窗口的组合。时间必须满足 `浏览 < 加购 < 购买 ≤ 首次浏览 + 24 小时`。收藏独立计数。
- 另计窗口内浏览后发生过购买的组合，检查其中有多少组合缺少可匹配的前序加购。同一用户可以浏览多个商品，因此分母是组合数。

## 结果与判断

| 匹配口径 | 可观察浏览组合 | 后续加购 | 完整浏览→加购→购买 | 浏览后购买 |
| --- | ---: | ---: | ---: | ---: |
| 同用户、同商品，24 小时 | 5,495 | 11 | 0 | 8 |
| 同用户、同商品，48 小时 | 4,963 | 23 | 0 | 10 |
| 同用户、同品类，24 小时 | 3,528 | 117 | 1 | 60 |

主口径下，11 ÷ 5,495 ≈ **0.20%**。品类 1004 有 876 个可观察组合，其中 2 个匹配到后续加购、0 个匹配到完整路径。延长至 48 小时仍未观测到完整路径，且完整观察窗口的筛选改变了分母。同品类匹配允许跨商品，各列的变化同时受归因粒度和分母影响。

主口径下，8 个浏览后购买的组合都缺少可匹配的前序加购。当前样本只支持描述匹配结果，真实用户流失、直接购买、事件漏记以及抽样造成的路径中断仍需区分。优先检查抽样是否保留同一用户、同一商品的连续事件，再核对浏览、加购和订单事件的用户键、商品键与时间戳，以及是否存在独立的立即购买入口。

## 实验方案

埋点和归因核对通过后，可测试详情页「一键加购」。按用户随机固定分组，以每位用户首次符合条件的详情页曝光为起点。主指标为 7 日加购用户率，护栏为同批用户的 7 日购买率，分母均为具有完整 7 日观测的合格曝光用户。上线前用真实基线和最小可检测效果估算样本量。这是实验设计，尚未执行。

## 复算

先通过项目的数据清洗 Notebook 生成本地 `output/data_clean.csv`，或准备包含 `user_id`、`item_id`、`category_id`、`behavior_type` 与 Unix 秒级 `timestamp` 列的清洗日志。脚本仅读取该文件，用 Python 标准库在内存中执行 SQLite 查询，输出整体和分品类汇总。作品集提供[运行脚本](sql/run-ordered-funnel.py)和[顺序匹配 SQL](sql/ordered-funnel-24h.sql)，原始日志保存在本地。

```bash
python sql/run-ordered-funnel.py /path/to/output/data_clean.csv
python sql/run-ordered-funnel.py /path/to/output/data_clean.csv --hours 48
python sql/run-ordered-funnel.py /path/to/output/data_clean.csv --grain category
```
